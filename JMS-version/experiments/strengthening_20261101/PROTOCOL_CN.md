# 独立补强实现与验解协议

## 范围

此目录为独立入口，读取 `model4_pjob_fifo_20261029` 和已冻结实验的代码与赋值，不修改它们。`prepare` 保存代码、输入、环境和预算的哈希及代码副本；`resume` 检查一致性。每个工作进程仅求解一个任务，结束后释放其模型内存。

## 固定结构的代入精修

精修固定的变量集合与前一批节拍实验一致：全部0–1/整数变量，排除以 `sync_` 开头的同步选择。将这些已固定变量代入原模型生成过程；时刻、等待和节拍辅助变量及同步选择保持决策状态。只删除恒真约束或在原变量界上可证明恒真的线性约束；恒假约束触发错误。不以原起点中的时间值固定时间变量。

保持原产品回片完工时间上界，目标为 `sum(wait) + 10*max_wait + weight*sum(rhythm)`。权重取0、5、25、100，每组60秒、单线程，SCIP分离参数与前批次相同。三个种子的输入来自原交叉实验对应主阶段，四个权重不串用其他权重的输出。

求解后，用原固定变量与新自由变量恢复完整赋值，重新构建未经修改的完整模型，检查全部原约束、实际晶圆解码和独立物理重放。完整约束验解无优化调用，额外耗时单独记录。可行、时间限制、内存限制及精修子问题最优状态分别保留；精修最优不等于完整调度问题最优。

## 成员表示的受控对照

Pjob臂使用原库存选择变量 `x[g,p,r]`，其中 `g` 为非空Pjob–LP组，`p` 为产品对候选位置，`r` 为该对的成员位置。逐片臂将它代为 `sum(y[w,p,r] for w in g)`；每片晶圆的选择变量之和等于1。对每片晶圆引入取片时刻，绑定其被选位置的取片事件，并对同一Pjob的相邻全局序号施加正处理时长间隔。

模式资格、腔室资格、跨LP顺序边界、禁止同Pjob同步取片、机器人容量及所有物理约束均从同一后端生成。逐片臂保留了组层的有效约束，新增的是明确晶圆身份所需的选择和时刻关联。两臂使用相同候选容量；`max_pairs`、`max_cycles` 不作单臂缩减。

映射依据：逐片可行解按组求和可得到Pjob赋值；Pjob可行解按解码后的严格全局取片顺序给各位置填入具体晶圆，可得到逐片赋值。两种映射都保留全部设备动作和时刻。运行时检查逐片选择身份是否与严格FIFO解码一致，并将最终赋值投影回完整原模型验解。

这是对成员身份表示的比较，产品动作仍按产品对位置索引。它不重建旧版逐片路线模型，也不把旧版跨LP规则带入新比较。报告整体模型规模和实测耗时时，将选择列的理论减少与整模型变化分开。三种子是在同一实例上的重复，不作为三个独立生产实例。

实例为8片、16片与三种配方的6个组合。两臂每组各300秒，采用同一份历史SPBS完整赋值作为物理起点，离线起点构造成本不混入主阶段预算。依种子交替两臂执行顺序；单线程、串行运行，记录进程资源。对照以各实例内配对结果为单位，不预设哪一种表示更快或取得更好排程。

## 不求解的入口验证

`verify_entries.py` 仅构建模型、映射赋值和验解，不调用 `optimize` 或 `presolve`。覆盖六种比较实例、三份24片精修起点、一组Pjob臂，以及同时包含CH2专用、CH3专用和双腔室资格的输入；还检查严格FIFO是否拒绝交换同一Pjob内两片晶圆身份，以及代入消元是否保留有效约束并拒绝矛盾常量行。报告保存为 `entry_validation.json`，逐项记录代码及输入哈希。

入口检查通过只说明建模与赋值映射通过检查。正式的精修改善、运行时间和内存收益来自上述两套命令完成后的实际输出，不由入口检查推断。
