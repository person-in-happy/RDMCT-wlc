“数量下界”表示：**在该固定配置内，至少有这么多种可行排程**，不是实际总数。此前的N!下界来自逐产品处理的构造：N个有身份产品的首次取片顺序可任意排列；其他动作按已经验证的规则补齐。8!为40,320，16!为20,922,789,888,000，32!为263,130,836,933,693,530,167,218,012,160,000,000，约为2.63×10³⁵。实际还存在其他配对、交错搬运与双腔并行顺序。

文件名和首行标题现已统一写明“已列数量”和“每配置至少数量”。“精确总数尚未求得”的原因是尚未完成全部结构的去重计数，而非没有任何规模信息。当前不能据抽取比例推断总量，也不能把N!写成“总数约等于N!”；它只提供有构造依据的下界。该结论使用原模型100000秒时域，未附加“必须最优”或更紧的Cmax限制。

新的三个文件采用你要求的格式：**只列晶圆、ATR/VTR取放动作和位置，按动作开始时间排序**。不列开始/结束标签、时间数值、旋转及加工/清洁曝光。清洁过程实际需要的辅助片取放仍然保留。省略的过程与全部时间仍在可重建的完整证据中，不能因为在文本中隐藏，就认为它们不存在。

## 读取格式

```text
LP1.1 ATR取 LP1 -> LP1.1 ATR放 AL -> LP1.1 ATR取 AL -> LP1.1 ATR放 LL上层
```

上面只是格式说明，文件内每条记录均完整展开。

- `PEC1`为模型辅助片D1，不是机械手手爪编号。
- `PEC1+PEC2 VTR放 CH1`为一对晶圆共享的腔室装载动作，不拆成两个先后动作。
- `{动作A || 动作B}`表示开始时间相同。`->`只表示开始先后，**不意味着前一动作已经结束**。
- 隐去加工、旋转和结束边界后，多个完整排程可能投影为同一简化序列；本次按简化序列重新去重，文件计数采用这个新口径。

## 为什么能扩大而不重复求解每条

这次采用“已验证时间模板＋产品身份置换”。时间、配对位置、腔室周期、清洁位置、辅助片使用和手爪分配均不改变。每个模板的所有产品工艺相同，每对最多一个产品，置换为同一组产品身份的双射后，路线、资源占用和曝光次数保持成立。

跨LP置换唯一可能改变的数值约束是LP到LP的ATR搬运间隔。程序对每个模板检查所有不同产品的LP端动作间隔，确认至少达到最坏情况下的3秒要求，再允许任意产品身份置换；其他位置间搬运参数不依赖LP编号。本批模板的最小该间隔为8秒。每条输出检查映射为双射，并检验序列没有重复；每个模板/配置另选首、中、末三个排列进行完整物理验解，核对置换后实际见证。

因此，**不是把任意动作排列直接当成可行解**。也不声称对全部150,320条分别运行了MILP或完整物理验解：可行性依赖模板验解、上述保持约束的置换证明及逐条映射检查；代表性见证有额外完整重验。具体记录见 `simple_manifest.json`、`simple_evidence/*templates.json.gz` 和索引。

所有结果仍是串行构造族的子集，不是最优排程集，也不是全空间完整枚举。原来的192条详细版本保留，避免丢失原证据。

## 大文件中提取一条并重验

Git保存六个文本文件的无损`.txt.gz`压缩版本，本地已有文本保留。新克隆后先执行`G:\conda\envs\a3cenv\python.exe -X utf8 JMS-version/tools/package_feasible_order_exports.py --restore`，按`compressed_exports.json`校验并还原文本，再使用下面的按编号提取命令。

大文件无需整体加载。以下命令将32片第60,000条提取到一个新目录，同时重建该条所有适用配置的完整时间见证并进行独立物理验解：

```powershell
Set-Location D:\git\git\RDMCT-A3C
G:\conda\envs\a3cenv\python.exe -X utf8 JMS-version/tools/extract_simple_feasible_order.py --n 32 --id 60000 --output JMS-version/gif/kexingyu/extracted_32_60000
```

输出目录必须尚不存在。可修改 `--n`、`--id` 和输出目录，读取其他记录。导出器为 `JMS-version/tools/export_simple_feasible_orders.py`；其运行源码快照保存在 `simple_evidence`。
