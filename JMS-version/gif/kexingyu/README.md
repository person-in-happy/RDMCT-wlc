## 空间至少有多大

在上述每一个固定配置内，都可构造如下子族：任选一个腔室，每次仅加工一个产品；4×1执行一次生产曝光，2×2执行连续两次曝光，其他位置用辅助片补齐；该产品回片、腔室卸空后清洁，再处理下一个产品。每批后的计数分别为1或2，均允许在H=3或H=10之前清洁。

将N个有身份的产品任意排列，每次按同一单产品批次执行，就得到N!条不同动作顺序。首次产品LP取片的身份顺序不同，保证它们不会被本目录的去重规则合并。这只是下界，不是精确计数。

| 产品数N | 每个固定配置的构造性下界N! | 同一构造族的完整动作终点：4×1 / 2×2 |
|---|---:|---:|
| 8 | 40,320 | 6,704 / 6,800秒 |
| 16 | 20,922,789,888,000 | 13,408 / 13,600秒 |
| 32 | 263,130,836,933,693,530,167,218,012,160,000,000 | 26,816 / 27,200秒 |

该提前清洁构造每产品用时分别为838秒和850秒，含清洁及辅助片归还。所有产品工艺相同，LP间搬运参数统一，上一产品及清洁已全部完成后才进入下一批，因此产品身份置换不增加此完整时域。全部三种规模均小于100000秒。四组单产品批次另经过原始完整MILP的固定排程可行性检查；12组规模/配置的构造及本次全部768条记录经过物理验解。这个论证没有把“所有可能排列都可行”泛化到任意动作排列，只证明上述特定串行构造族。

因此，即使只写出16!条，假设每条只占1 KB，也已约20.9 PB；实际完整32片动作链更长。32片下界约为2.63×10³⁵。不能承诺将这些全部展开到普通文件中。

## 怎样阅读动作链

例式：

```text
{ START LP1.1 ATR pick from LP1 }
 -> { END LP1.1 ATR pick from LP1 }
 -> { START LP1.1 ATR place to AL }
 -> ...
```

这里的省略号仅用于README说明，三个主文件内每条链均完整展开。

- `LP1.1`对应模型产品身份`LP1_W1`。
- `PEC1`对应模型辅助片身份`D1`，不是VTR手爪编号；`PECstorage(VS)`为真空辅助片库。
- `[LP1.1+PEC3] VTR place to CH1`是同一对晶圆的腔室装载动作，不能重复计成两个独立腔室动作。
- `START`和`END`描述动作边界；`->`表示边界先后；同一大括号中的`||`表示同时发生的边界。某动作开始到结束之间可出现其他动作边界，因此这种表示不会丢失并行关系。
- 取放、腔室旋转、生产曝光、清洁曝光全部列出。搬运间隔、AL对准、抽气/放气和复位在模型中部分以时间下限/占用表达，不额外杜撰独立动作。相应约束通过数值时间证据验证。
- 具体秒数不参与去重；同一动作身份序列、起止边界顺序与同时关系相同就计一次。不同手爪分配或仅改变等待长度而不改变这些边界关系，不另算新顺序。

## 验证范围与可复核文件

`evidence/*wafer-witnesses.jsonl.gz`保存每个配置记录的完整时间见证、产品/辅助片身份、配对、腔室周期、VTR手爪以及独立验证结果。`manifest.json`保存文件哈希、源码哈希、构造规则、去重计数和下界；其中`all_feasible_orders`为`null`，`complete_enumeration`为`false`。

逐条执行了产品覆盖、路线、资源容量、机器人旅行间隔、手爪、辅助片复用、腔室前后侧、曝光次数、可选清洁与强制阈值等物理检查，另检查时间域、候选数量和标签规范。**未对每条8/16/32片记录重新建立完整MILP做求解器可行性认证，也不声称这些串行示例最优。** 原始模型单产品批次检查只是构造依据的补充，不能冒充整个规模的最优认证。
