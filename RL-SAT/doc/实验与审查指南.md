# RL-SAT 实验与审查指南

本指南给出一条可直接执行的完整流程：环境隔离 → smoke 验证 → RL-SAT 训练 → 单实例求解 → 旧算法四组消融 → RL-SAT 三组消融 → 4+3 联合报告与同功能甘特图 → 审查归档。

除明确标注“旧算法环境”的命令外，命令均在 `D:\git\git\RDMCT-A3C\RL-SAT` 执行。

## 1. 实验组与结论边界

联合消融必须保留以下七组，不能用 RL-SAT 的组替换旧组：

| 系列 | 方法键 | 含义 |
|---|---|---|
| 旧 MIP/SCIP | `solver_only` | SCIP 默认割选择 |
| 旧 MIP/SCIP | `a3c_only` | 仅 A3C 割选择 |
| 旧 MIP/SCIP | `beam_only` | 仅结构重排/beam |
| 旧 MIP/SCIP | `a3c_beam` | A3C + 结构重排 |
| RL-SAT | `initial_cp_sat` | 确定性初始方案 + CP-SAT |
| RL-SAT | `heuristic_beam_cp_sat` | 启发式 beam + CP-SAT |
| RL-SAT | `a3c_beam_cp_sat` | A3C beam + CP-SAT |

必须分开解释两类证书：

- 旧四组求解的是原 Petri MIP，bound/gap 属于 SCIP/MIP 范围；
- RL-SAT 动态模式使用 `certificate_scope=dynamic_chamber_assignment_cp_sat_abstraction`，固定基线仍使用 `canonical_assignment_cp_sat_abstraction`；单次 bound/gap 只证明所选分腔候选的 CP-SAT 子模型；
- 两类算法可以比较同一物理实例上的可行调度 `Cmax` 和同硬件、同预算下的端到端时间，但不能把两类 bound 合并为一个“全局 gap”。

RL-SAT 主配置 `smoke/train/experiment` 使用：

```json
"allow_dynamic_chamber_assignment": true
```

这表示保持晶圆 pair 与4x1批成员不变，但允许初始解、A3C/beam 把完整4x1批或2x2单元分配到 CH2/CH3，并按候选实际工艺周期重新生成清洗。`configs/ablation.json` 显式设为 `false`，作为修改前固定 canonical 分腔消融。动作语义已经改变，正式动态分腔实验必须重新训练 checkpoint；旧 RL-SAT checkpoint 只能做兼容性诊断，不能作为正式新算法模型。

目标仍是严格两阶段而不是加权折中：阶段1最小化 `Cmax`；阶段2加入 `Cmax <= 阶段1 incumbent` 后，最小化释放等待、LLupper、工艺前腔室等待、处理后、LLlower等待以及 CH2/CH3 汇总 idle 的平方和。`schedule_stability` 单位为 `s²`，阶段2不能降低 WPH。
PEC 在当前模型中没有具有物理意义的固定身份；模型只约束池容量和每个 job 的占用窗口。为便于审图，甘特图执行确定性的“仅显示用”区间着色：

- 按 `vtr_load` 开始时间排序，依次分配 PEC1、PEC2、…、PECN，使用到 PECN 后从 PEC1 循环；
- 如果轮到的 PEC 尚未返回 storage，则跳过它并寻找下一个空闲 PEC，绝不制造同一泳道重叠；
- 同一显示 PEC 的两次 job 之间用 `PEC storage wait` 连续连接；
- 该编号是匿名同质 PEC 的一种可行可视化，不应在论文中解释为模型追踪了真实序列号。

## 5. 审查甘特图正确性

打开：

```text
D:\git\git\RDMCT-A3C\RL-SAT\results\smoke-solve\petri_gantt\index.html
```

完整路径图实行强校验。任一实体泳道出现未覆盖时间段或重叠时，渲染器直接抛出 `Invalid wafer path schedule`，不会静默生成错误图。

产品晶圆的物理位置序列应为：

```text
LP → ATR → AL → ATR → LLupper → VTR → CH → VTR → LLlower → ATR → LP
```

图中可能显示 `AL wait`、`CH wait`、`LLupper wait` 等驻留块；这些块用于填满同一晶圆在当前位置的连续驻留时间，不改变上述位置序列。两片成对进入 AL 时，一片先校准、另一片由 ATR 保持；共享的 AL exchange 会投影到两片晶圆，且不能造成间隙或重叠。

匿名 PEC 的每次占用在显示泳道上的物理位置序列应为：

```text
PEC storage → VTR → CH → VTR → PEC storage
```

若同时需要两片 PEC，应依次占用 PEC1、PEC2；后续 job 使用 PEC3，直到 PEC pool 末尾后循环到 PEC1。循环时必须跳过仍在 CH/VTR 中的显示 token。同一显示 token 的多次 job 保持在同一泳道，中间用 `PEC storage wait` 连续连接。

交互功能验收：

- 方法、实例和 `full/chambers/resources` 三类视图可切换；
- 鼠标滚轮可按指针位置缩放；
- 鼠标按下拖动可横向平移；
- 复位按钮恢复全局视野；
- `manifest.json` 中每张 SVG 都有对应记录；
- 联合消融时首页显示 `comparison.svg`。

### 6.2 通用晶圆输入组合复核

动态分腔不是按 `10+10` 写死的。建模单位由输入数量自动形成：4×1 每四片形成一个满批，允许 1～3 片尾批；2×2 每两片形成一个工艺对，允许单片尾对；每个完整单位都可分配到 CH2 或 CH3。分腔后会按各腔实际工艺暴露次数重新插入清洁，不沿用固定奇偶队列的清洁位置。

先运行覆盖输入类别的自动化矩阵：

```powershell
python -m pytest `
  tests/test_canonical_structure.py::test_dynamic_initial_plan_supports_all_mode_combinations `
  tests/test_cpsat_integration.py::test_dynamic_solver_supports_general_input_matrix `
  tests/test_cpsat_integration.py::test_dynamic_tail_combinations_render_continuous_compatible_gantt `
  -q
```

当前矩阵不是只重复一个规模，而是覆盖：

| 类别 | 回归输入 `(4×1片数, 2×2片数, 清洁间隔)` |
|---|---|
| 纯4×1、含尾批 | `(1,0,0)`、`(5,0,2)` |
| 纯4×1、动态分腔后触发清洁 | `(9,0,1)`；结构层另测 `(20,0,2)` |
| 纯2×2、含单片尾对 | `(0,1,0)`、`(0,3,3)` |
| 纯2×2、长链并触发清洁 | `(0,10,3)` |
| 混合、两种模式均有尾批 | `(1,1,0)`、`(2,2,2)`、`(3,3,5)`、结构层 `(5,7,4)` |
| 正式对照规模 | `(10,10,5)` |

求解层的每个用例都检查：全部产品片均有完成时间、所有任务落在 `0..Cmax`、ATR/AL/VTR/CH2/CH3 无资源重叠、候选覆盖全部工艺单位，并且证书范围为动态分腔 CP-SAT 抽象。结构层还检查每个腔室都保持“4×1 在 2×2 之前”的设备工艺规则。另对纯4×1单片尾批、纯2×2单片尾对和1+1混合组合实际生成三视图兼容甘特图；连续泳道校验若发现空洞或重叠会直接使测试失败。

运行任意目标组合时，从正式配置复制一个实例配置，只改输入与输出名。例如下列命令可直接把 `$Full`、`$Mix`、`$CleanInterval` 换成所需值：

```powershell
$Full = 5
$Mix = 7
$CleanInterval = 4
$CaseName = "dynamic-${Full}full-${Mix}mix-c${CleanInterval}"
$CfgPath = Join-Path 'configs' "${CaseName}.json"
$Cfg = Get-Content configs\experiment.json -Raw | ConvertFrom-Json
$Cfg.tool.process_mode = 'mixed'
$Cfg.tool.mode_4x1_wafers = $Full
$Cfg.tool.mode_2x2_wafers = $Mix
$Cfg.tool.cleaning_interval = $CleanInterval
$Cfg.tool.allow_dynamic_chamber_assignment = $true
$Cfg.output.run_name = $CaseName
$Cfg.output.output_dir = "results/${CaseName}"
[IO.File]::WriteAllText(
  (Join-Path (Get-Location) $CfgPath),
  ($Cfg | ConvertTo-Json -Depth 20),
  [Text.UTF8Encoding]::new($false)
)
python scripts\solve.py --config $CfgPath --output-dir "results\${CaseName}" --device cpu
```

输入边界由设备配置决定，而不是由 `10+10` 决定：产品片总数至少为1，默认四个 LP、每个25槽时总数不超过100；若含2×2，清洁间隔不能为1（相邻两次暴露不能被清洁拆开）；`cleaning_interval=0` 表示关闭清洁；默认双腔 PEC 配置要求池大小至少8且为偶数。超过这些边界应修改真实设备容量或工艺约束，不能仅为通过算例绕过校验。

同一个 A3C 网络可以对不同数量的工艺单位产生可变长动作分数，未加载 checkpoint 时的 initial/heuristic Beam/CP-SAT 也不依赖固定规模。但正式性能对比仍应在目标输入分布上重新训练或明确标注为跨规模迁移测试；“能正确求解任意合法组合”和“某个 checkpoint 对所有规模都有相同质量”是两个不同结论。

### 7.1 热启动、甘特图和独立指标图的强制检查

从本版本开始，SPBS 先得到物理调度，再在完整二阶段平方模型中补齐 `resource_idle_*`、平方辅助变量和 `schedule_stability`，最后才写入 `.sol`。加载时还会执行完整可行性校验。详细日志必须出现：

```text
loaded feasible Petri warm start: ... (stored=True)
```

若出现 `rejected incomplete or infeasible Petri warm start`，不要继续把该次结果作为正式实验；应重新生成热启动。`stored=True` 不能单独证明旧格式热启动是 incumbent，必须同时有前面的 `loaded feasible`。

本项目中 2026-07-29 首次运行的 `17+17,c5` 结果四组均为 `timelimit` 且 `has_solution=false`，所以没有可画的产品/PEC 调度。此时甘特图目录只有首页和 manifest 是正确的失败诊断，不能用零值或部分解伪造甘特图。该次无解结果也不能用于判断四种算法的调度质量差异。

每次旧四组消融现在输出一个总览 `*_comparison.svg`，并额外输出七张可单独放入论文或审查材料的图：`*_feasibility.svg`、`*_objective.svg`、`*_gap.svg`、`*_pdi.svg`、`*_time.svg`、`*_callback.svg`、`*_nodes.svg`。文件列表记录在 JSON 的 `artifacts.metric_svgs`。其中：

- 先看 feasibility；任何方法为 0% 时，该方法的 Cmax、Gap 和 PDI 都不能用于排名；
- 固定晶圆数下 `objective=Cmax` 越小即 WPH 越大；
- 正式算法性能主看 PDI，并同时报告 Cmax、Gap、时间、节点和 callback 开销；
- 单个实例不能形成统计结论；至少使用多个实例与多个 seed 做配对比较；
- 只有 `has_solution=true` 的方法才生成甘特图。四组均无 incumbent 时，不存在可比较的甘特调度。

运行后快速审查：

```powershell
$LegacyJson = Get-ChildItem "ablation_results\rl_sat_compare_matrix\${CaseName}_rerun" -Filter 'ablation_*.json' |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1 -ExpandProperty FullName
$R = Get-Content $LegacyJson -Raw | ConvertFrom-Json
$R.summary | ConvertTo-Json -Depth 5
$R.artifacts.metric_svgs
$R.artifacts.gantt_error

$NoIncumbent = $R.results.PSObject.Properties.Value |
  ForEach-Object { $_ } |
  Where-Object { -not $_.has_solution }
if ($NoIncumbent) { Write-Warning '仍有方法没有 incumbent；先看详细日志，不要用甘特图判断性能。' }
```

正式矩阵中每个组合都要把旧四组和 RL-SAT 三组放在同一个实例语义、同一工艺时间和同一求解预算下比较。若复用固定 checkpoint，应把结果标为跨规模迁移；若要比较各规模的最好学习性能，则应对两条学习链路分别按同一训练协议重训。
默认 `--console_mode progress` 时，PowerShell 只保留一条按“实例×方法”计数的 `Ablation` 进度条，不再逐行显示 SCIP、A3C 推理、两阶段状态和产物路径。全部详细输出写到：

```text
<output_dir>\ablation_<instance_type>_<timestamp>.log
```

同一路径也记录在对应 JSON 的 `meta.detailed_log_file`。运行中或结束后可另开 PowerShell 审查，不影响主终端进度条：

```powershell
$DetailLog = Get-ChildItem ablation_results\rl_sat_compare_gpu -Filter 'ablation_*.log' |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1 -ExpandProperty FullName
Get-Content $DetailLog -Wait
```

只有临时诊断时才使用 `--console_mode full` 恢复旧式逐行输出；正式实验保持 `progress`。`run_petri_a3c_beam.py` 同样默认只显示 `Petri A3C+Beam` 进度条：包装器日志为 `runtime_<instance>_wrapper.log`，子求解器日志为 `runtime_<instance>_solver.log`。
详细日志文件还必须出现 `reserved lexicographic stability budget` 和 `lexicographic phase 2 (stability)`；若显示 `stability_time=0s` 或 `stability_status=not_run`，本次不是完整两阶段实验。新增的两个 CLI 参数对 `solver_only,a3c_only,beam_only,a3c_beam` 四组统一生效，不改变消融公平性。

详细日志文件必须出现 `A3C policy inference device: cuda:0`。GPU 只执行 `a3c_only`/`a3c_beam` 的 PyTorch 推理；`solver_only`、`beam_only` 以及 SCIP 的 LP、分支定界和启发式仍使用 CPU。日志中的网络推理只有毫秒量级时，增加 GPU 不会显著缩短数百或数千秒的 SCIP 求解。

还要在详细日志文件中核对 `effective SCIP limits: time=...`。命令传入 `--time_limit 3000` 时应显示 `time=3000.0s`；若仍显示 `800.0s`，说明实际执行的命令或进程不是上述参数。旧算法使用 3000 秒而 RL-SAT 配置仍为 300 秒时，不得直接比较求解时间；应统一预算或只把它标为非对称诊断实验。
