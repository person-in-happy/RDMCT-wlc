# RL-SAT 改进算法说明

## 1. 目标与非目标

RL-SAT 的目标是在不改变原 `RDMCT-A3C` 功能的前提下，增加一条完全绕过 SCIP 的求解路径，并复用原项目中“先构造高质量结构、再搜索改进”的核心思路：

1. 从设备参数构造 canonical pair 与不可拆分4x1批，保留标签对称消除；
2. 由结构化初始解按工艺周期和清洗负载平衡 CH2/CH3；
3. 由 A3C 和结构感知 beam search为完整4x1批/2x2单元选择腔室；
4. 由 OR-Tools CP-SAT 对每个候选分腔重建清洗并精排详细时序；
5. 先最小化 Cmax，再在 Cmax 不恶化时最小化各阶段等待与双腔汇总 idle 的平方和；
6. 输出可审计结果和与原项目用途一致的甘特图。

本扩展不是把 SCIP 模型逐行翻译成 CP-SAT，也不宣称已证明与原 MIP 的完整可行域等价。学习层改变候选 CH 分配但不绕过物理约束；CP-SAT 负责每个候选子模型内的可行性与时间优化。有限 beam 没有枚举所有分腔组合，效率与解质量收益必须通过实验验证。

## 2. 隔离架构

所有新增内容位于 `RL-SAT/`：

```text
RL-SAT/
  configs/                 显式、版本化实验参数
  doc/                     算法与复现实验说明
  rl_sat/
    config.py              配置、校验和整数时间缩放
    domain.py              canonical pair、结构单元、Plan、ScheduleResult
    initial_solution.py    确定性初始分腔与旧 .sol canonical 一致性检查
    environment.py         结构感知 MDP 和硬动作掩码
    model.py               actor-critic 网络与独立 checkpoint schema
    a3c.py                 多 worker A3C 训练
    beam_search.py          策略/启发式 beam 与候选去重
    cpsat_solver.py         候选 chamber assignment 抽象的 CP-SAT 精排
    hybrid_solver.py        初始解、beam、CP-SAT 的编排
    result_io.py            结果 JSON 与旧式 solution 映射
    gantt.py                无外部绘图库的 SVG 甘特图
  scripts/
    train.py
    solve.py
    benchmark.py
    verify_no_scip.py
    render_gantt.py
```

新入口不导入 `petri_mip_generator.py`、`scip_imports.py` 或 `pyscipopt`。原项目文件、入口、checkpoint 和结果目录均不需要改变。RL-SAT 使用自己的 `rl_sat_checkpoint_v1`；原 A3C 模型学习的是 SCIP cut 特征，状态/动作含义不同，不能直接当作本模块的资源调度 checkpoint。

## 3. 问题结构

### 3.1 显式设备配置

输入配置分为：

- `tool`：设备数量、晶圆模式、转运/工艺/清洗时间、PEC 与端口容量；
- `rl`：A3C 网络、学习率、折扣、熵、worker 和训练轮数；
- `beam`：宽度、每节点展开数、候选数和评分权重；
- `cpsat`：时间整数化、候选预算、最终 polish 预算和求解线程；
- `output`：运行名、结果目录、兼容结果与甘特图开关。

CP-SAT 只接受整数系数。设输入时间为 \(t\)，`time_scale=s`，内部时间为

\[
\hat t = t \times s.
\]

当 `require_exact_scaling=true` 时，若 \(\hat t\) 不是整数则配置校验失败，不会静默四舍五入。

必须注意旧项目中的默认值漂移：

| 参数 | 原 `PetriMIPConfig` dataclass 默认 | 原 CLI 默认 |
|---|---:|---:|
| `full_process_time` | 180 | 80 |
| 2x2 process time | 180 | 30 |
| `cleaning_interval` | 5 | 10 |

因此 RL-SAT 的可重复实验必须保存完整 JSON，并在与旧链路比较前统一这三项及其他设备参数。只写“采用默认值”不足以支持复现或公平对比。

### 3.2 canonical pair、结构单元与可选分腔

产品晶圆仍按模式内部到达顺序每两片形成 `F1...`、`M1...`，末尾不足两片时自动形成单片尾对；最多两个连续 full pair 组成一个不可拆分的4x1单元 `FBk`，因此也支持不足4片的4x1尾批；每个 mix pair 形成一个2x2单元 `MUk`。单位数完全由输入片数计算，不依赖10+10或其他固定规模，同时保留 pair/批成员的标签对称消除。

`tool.allow_dynamic_chamber_assignment` 控制分腔边界：

- `false`：`Plan.chamber_units` 必须等于原 canonical CH2/CH3 队列，用于修改前消融；
- `true`：完整 `FBk`/`MUk` 可以分到 CH2 或 CH3；每腔仍要求4x1先于2x2，不能拆分4x1批。

动态模式下，清洗不是从旧 canonical 位置复制，而是按候选在每个腔室的实际 full 周期和连续2x2曝光数重新构造。`dispatch_order` 保存动作顺序，候选签名同时包含 `unit@CH`，不同分腔不会被错误去重。

## 4. 第一层：初始解、A3C 与结构感知 beam

### 4.1 确定性初始解

兼容模式原样生成 canonical 队列。动态模式按 `unit_order` 逐个处理结构单元，分别试放 CH2/CH3，并按以下字典序选择：预计峰值负载、双腔不平衡、清洗次数、腔室编号。负载估计按候选实际连续2x2段计算共享曝光，因而能识别“平衡后正好不触发清洗”的方案。

无旧 `.sol` 也始终能生成完整可行候选。若提供旧 `.sol`，当前只检查可识别正 assignment 的结构一致性；动态正式实验不会把旧连续时刻或旧 cut 状态注入 CP-SAT。

### 4.2 结构感知 MDP

状态仍由单元、腔室和全局张量组成，包含模式、产品/PEC数、工艺周期、候选负载、full/mix数量、清洗状态和负载不平衡。

动态模式保留单元身份顺序以消除同类标签排列，只让策略决定下一个单元的腔室：

\[
a_t=(u_t,c_t),\qquad c_t\in\{CH2,CH3\}.
\]

动作掩码只开放当前未分配单元的两个腔室动作，并保证每个单元恰好分配一次、4x1批不拆分、每腔4x1先于2x2。兼容模式继续开放两个 canonical 队头。网络不输出开始/结束时间；所有物理可行性仍由 CP-SAT 检查。

### 4.3 奖励与 A3C

令结构势函数为

\[
\Phi(P)=LB(P)+0.10\,I(P)+0.02\,N_{\mathrm{clean}}(P)T_{\mathrm{clean}},
\]

其中 \(LB\) 是基于 CH、ATR/AL 负载的启发式下界，\(I\) 是 CH 负载不平衡。一步奖励为规范化后的势函数改进：

\[
r_t=-\frac{\Phi(P_{t+1})-\Phi(P_t)}{K}.
\]

完整分腔序列另加不平衡惩罚。动态模式下 actor 对当前结构单元的 CH2/CH3 两个合法动作输出 masked policy，兼容模式才在两个 canonical 队头之间选择；critic 估计状态价值。训练损失由 policy loss、value loss 与 entropy regularization 组成。多个 worker 使用不同随机轨迹采样，在受控更新区把梯度同步到共享模型。梯度裁剪和周期 checkpoint 降低训练不稳定性。

动态模式下 A3C 学的是结构单元到 CH2/CH3 的候选分配；兼容模式学的是固定队列 release 优先级。两种模式都不直接输出物理约束或开始/结束时间，详细可行性仍由 CP-SAT 检验，因此神经网络数值误差不能绕过资源约束。

### 4.4 beam search

beam 节点保存部分分腔 Plan、累计策略对数概率和结构估价。评分继续组合策略概率、预计峰值负载和双腔不平衡；无 checkpoint 时使用相同估价器产生启发式候选。

动态模式每步展开当前单元的 CH2/CH3 两个选择，按包含 `unit@CH` 的签名去重并施加多样性奖励；完成后最多输出 `candidates_for_cpsat` 个不同分腔候选。初始解与 beam 候选再次按同一分腔签名合并。旧动作语义是固定队列 release，因此启用动态模式后正式 A3C 实验必须重新训练 checkpoint。

## 5. 第二层：候选分腔 CP-SAT 精排

每个动态 Plan 固定一个完整结构单元到 CH2/CH3 的候选分配。CP-SAT 为该候选按每腔实际 full/mix 周期重建工艺段与清洗 epoch，再优化任务开始/结束时间、共享资源次序和 LL 槽选择；`dispatch_order` 只转换为搜索 hint。不同候选是不同分腔子模型，不是同一可行域的重复 hint。

精排模型覆盖以下约束族：

- 产品路径前后关系：`LP → ATR → AL → ATR → LLupper → VTR → CH → VTR → LLlower → ATR → LP`；
- PEC 路径：`PEC storage → VTR → CH → VTR → PEC storage`；
- ATR、AL、VTR 和腔体的互斥占用；
- VTR mandatory circuit 与端点相关的空载 reposition：端点相同为 0，不同为 `pair_transfer_time`；
- LLupper/LLlower 槽容量及等待占用；
- `4x1` 的四片装载、旋转、处理与反向卸载；
- `2x2` 的边界曝光、内部曝光、桥接装卸和连续段；
- 每个 CH 的 PEC 配额与占用；
- 清洗间隔、清洗装卸和清洗处理；
- 模块驻留时间及 `max_schedule_wait_time>0` 时启用的等待上限；
- 所有产品完成时间与 \(C_{\max}\)。

具体求解采用严格两级目标：

1. 主目标最小化 \(C_{\max}\)，固定晶圆数下等价于最大化 WPH；
2. 若启用 `lexicographic_stability` 且已有可行主目标，则添加 \(C_{\max}\le C_{\max}^{(1)}\) 约束，再最小化稳定性平方和

\[
S=\sum_p\left(r_p^2+w_{u,p}^2+w_{pm,p}^2+w_{post,p}^2+w_{l,p}^2\right)
  +I_{CH2}^2+I_{CH3}^2,
\]

其中 \(r_p\) 是产品 pair 在 LP 等待首次 ATR 服务的时间，\(w_{pm,p}\) 是装入腔室至开始工艺的等待，其余分别为 LLupper、处理后和 LLlower 等待；\(I_{CHm}\) 是 \([0,C_{max}]\) 内该腔室扣除处理、旋转和清洗动作后的汇总 idle。`schedule_stability` 单位为 `s²`。阶段2不能牺牲阶段1 WPH。

`chamber_idle_penalty`、`post_process_wait_penalty`、`ll_wait_penalty` 仍作为旧 schema 兼容字段保留；`max_robot_residency_time` 当前也为保留字段，尚未形成独立约束；`rl.structural_cost_weight` 尚未接入 environment、reward 或 beam 评分。

Hybrid 把 `time_limit_seconds` 作为一次 hybrid solve 内所有 CP-SAT 调用共享的总预算。实现先预留

\[
T_{\mathrm{reserve}}=\min(T_{\mathrm{polish}},T_{\mathrm{total}})
\]

用于可能的最终 polish；候选筛选每次以 `candidate_time_limit_seconds` 为上限，但会根据“总预算剩余量减去 polish 预留”截断，预算不足时停止继续候选。若已找到可行结果，polish 实际预算为 `min(final_polish_seconds, 当前剩余总预算)`；没有可行候选则不执行。polish 会把已选 incumbent 的任务 start/end 与 \(C_{\max}\) 作为 `AddHint` 复用，这些仍是 hint 而非硬约束。metadata 记录 proposed/evaluated candidate 数、各次 allocation、实际 screening/polish elapsed。beam、网络推理和 Python 编排不计入该 CP-SAT 共享预算，因此端到端墙钟时间可以略大于 `time_limit_seconds`。直接调用 `CPSATScheduler.solve()` 且不覆盖时限时，该字段也是单次 scheduler 的默认预算。

结果 metadata 的 `declared_abstractions` 明确列出当前与旧 Petri MIP 不能直接等同的三点：

- 两片晶圆的 ATR 前段服务被捆绑，占用 ATR 穿过串行、单槽的 AL 校准；
- VTR loaded exchange 使用 `pair_transfer_time`；mandatory 空载 reposition circuit 使用 `LLupper/LLlower/CH2/CH3/PEC_storage` 粗粒度端点，同端点为 0、端点变化时使用 `pair_transfer_time`；
- PEC 身份按每腔 cumulative token 容量做对称聚合；token 数量和 dwell window 仅在该抽象内精确。

## 6. 为什么可能比 SCIP 链路更高效

效率来源不是“CP-SAT 必然比 SCIP 快”，而是 canonical 对称消除、学习引导和 CP 传播的组合：

- canonical pair 和4x1批成员继续消除标签对称；动态模式把整批/2x2单元的 CH2/CH3 选择交给 A3C/beam，并按候选重建清洗；
- 初始解立即提供一个完整跨队 dispatch hint；
- A3C 与 beam 生成有限、多样的 dispatch 搜索起点；
- CP-SAT 可以利用 hint，但不会被错误 hint 限制可行域；
- 区间变量、`NoOverlap`/容量约束适合表达离散调度传播。

相对于旧 MIP，canonical 固定映射和上述显式抽象排除了非 canonical 决策或改变了部分物理细节；beam 本身只影响搜索 hint，不再排除额外 CP-SAT 解。多个 hint 重复求解同一模型也会增加预算。实际是否提速、解质量损失多少，必须在相同实例、相同设备参数、相同墙钟预算和相同硬件下实验。

## 7. 结果与甘特图

`result.json` 保存：

- 状态、目标、条件 best bound、墙钟时间；
- 选中的动态/canonical分腔、dispatch hint、候选来源及 `schedule_stability(s²)`；
- 规范化任务列表和晶圆/pair 完成时间；
- 候选数、阶段耗时、求解器状态和证书范围；
- 版本与配置快照或关联信息。

`legacy_solution.json` 将规范化任务投影为原项目常用的 `c_max`、产品 stage 起止和资源任务变量命名，便于已有分析脚本读取。它是兼容视图，不代表内部重新构造了 SCIP 变量或 SCIP 解对象。

甘特图完全从保存后的任务 JSON 生成，不导入求解器：

- `overview.svg`：调度总览；
- `resource.svg`：ATR/AL/LL/VTR/CH 等资源占用；
- `product.svg`：各产品晶圆的工艺路径；
- `manifest.json`：文件、资源、状态与摘要；
- `index.html`：三图浏览页。

甘特图适合人工查验顺序和重叠，但不是约束正确性的数学证明；自动测试和 CP-SAT 状态才是程序级验收依据。

## 8. 正确解释 bound、gap 与 OPTIMAL

设 beam 第 \(k\) 个候选分腔定义的 CP-SAT 可行域为 \(F_k\)：

\[
z_k^\star=\min_{x\in F_k}C_{max}(x).
\]

单次 CP-SAT 返回的 bound、gap 和 `OPTIMAL` 只证明该 \(F_k\) 内的详细时序。Hybrid 在有限候选集合 \(K\) 上返回 \(\min_{k\in K}\hat z_k\)，但有限 beam 没有枚举所有可能分腔，因此它既不是全部动态分腔的全局证明，也不是旧 SCIP Petri MIP 的全局证明。兼容模式只有固定 canonical 候选，证书范围相应标为 canonical 子模型。

建议报告字段写为：

```text
certificate_scope = dynamic_chamber_assignment_cp_sat_abstraction
candidate_assignment_role = rl_beam_candidate
all_assignment_global_gap = not_available
global_mip_gap = not_available
```

canonical 消融则使用 `canonical_assignment_cp_sat_abstraction`。实验表可以比较同语义实例的可行 `Cmax/WPH`，但必须分列旧 MIP gap、候选 CP-SAT gap 和端到端时间。
## 9. 当前支持与限制

当前支持：

- CH2/CH3 两个旋转腔；
- `4x1`、`2x2` 及混合模式；
- 每批四片、PEC 补位与每腔 PEC 配额；
- ATR/AL/LL/VTR 共享资源、清洗和模块驻留限制；
- 显式模式序列或按模式数量生成；
- 无 checkpoint 启发式运行、RL-SAT checkpoint、旧 `.sol` canonical 一致性检查；
- JSON 结果、旧式 solution 映射和三类 SVG 甘特图。

当前限制：

- `num_pm` 必须为 2，腔体标识固定为 CH2/CH3；
- `batch_size` 必须为 4；
- 产品 pair 与4x1批成员仍固定；动态模式搜索完整4x1批/2x2单元的 CH2/CH3 分配，但不拆批，也不在单次 CP-SAT 内穷举所有跨候选分腔；
- `allow_dynamic_chamber_assignment=false` 时保留固定 canonical 队列；设为 `true` 后 A3C/beam 动作含义改变，正式实验应重新训练 RL-SAT checkpoint；
- 旧 `.sol` 只做已识别正结构赋值的一致性检查，不恢复、补齐或 warm-start 旧解；
- 原 cut-selection A3C checkpoint 与 RL-SAT checkpoint 不兼容；
- 未对跨规模、跨工艺时间的策略泛化给出保证；
- 动态故障、实时重调度、维护人员等未显式建模；
- `max_robot_residency_time` 与三个 penalty 字段当前保留但未进入优化；
- 动态候选或 canonical CP-SAT 子模型的证明都不能当作原 MIP 或所有分腔组合的全局证明。

任何扩展设备数、批容量、配对方式或工艺穿插的修改，都应先更新 `domain.py` 的不变量、动作掩码、CP-SAT 约束和测试，再更新 schema 版本，不能只放宽配置校验。

## 10. 研究依据与使用方式

以下工作为架构设计提供启发，不构成 RL-SAT 性能、等价性或最优性的实验验证：

- Kim 与 Lee 研究了单臂组合设备中由深度强化学习和自适应搜索联合优化 robot task/release sequence 的方法，启发“学习排序 + 受约束搜索”的分层设计：[IEEE T-ASE, 2025](https://doi.org/10.1109/TASE.2024.3399818)。
- 2025 年 *Scientific Reports* 关于变化配置和清洗条件下组合设备调度的工作，支持把配置与清洗显式纳入结构状态的必要性：[DOI 10.1038/s41598-025-31722-7](https://doi.org/10.1038/s41598-025-31722-7)。
- Huang 等关于驻留约束与 load lock 协同的研究，提示精排必须保留 residency 与 LL 资源耦合：[IEEE T-ASE, 2025](https://doi.org/10.1109/TASE.2024.3507854)。
- Echeverria 等将 constraint programming 与深度学习用于柔性作业车间调度，启发把学习模型限制为搜索引导而由 CP 保证约束：[arXiv:2403.09249](https://arxiv.org/abs/2403.09249)。
- ICLR 2024 的 DRL-guided improvement search 工作支持用学习策略引导有限邻域/候选改进，而不是让网络直接替代组合优化器：[OpenReview](https://openreview.net/forum?id=jsWCmrsHHs)。
- 2026 年 *Advanced Engineering Informatics* 关于 non-cyclic single-arm cluster tool 与 DRL entry-sequence 的工作，为“学习跨队进入/释放顺序”提供了最新设计参照：[DOI 10.1016/j.aei.2026.104718](https://doi.org/10.1016/j.aei.2026.104718)。
- OR-Tools 官方说明强调 CP-SAT 在整数模型上工作，并定义 `OPTIMAL`、`FEASIBLE` 等状态；本项目据此实现时间缩放并限制证书表述：[CP-SAT Solver](https://developers.google.com/optimization/cp/cp_solver)。
