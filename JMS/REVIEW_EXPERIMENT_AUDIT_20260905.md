# 两项在运行补充实验的证据审查

审查快照：2026-09-05 09:45–09:50（Asia/Shanghai）。本文件是内部审稿/实验核查记录，不是已完成实验结果表。本次仅只读检查脚本、进程、LP、检查点和验证表；未启动、终止、修改或重新生成任一在运行实验。

## 1. 核心结论

第二项 `JMS/run_retry_no_incumbent_old_cmax.ps1 -TimeLimit 28800` 是对**旧完工口径下四个此前没有可行解的高频清洁难例进行延长限时重试**。它能补充旧网格的可行排程覆盖率与求解界信息，但不能直接补齐第一项产品完工口径下的清洁间隔阈值，也不能单独验证两阶段运行质量或 Proposed 相对其他方法的优势。

两个实验虽然使用相同等累计加工时长（4×1 为 180 s、2×2 为 90+90 s），但有不同的目标边界。**稿件必须将产品返回 LP 的完工时间和包含终端清洁卸片的完工时间分开，不能将两组最优值拼成一条曲线。**

## 2. 两项实验实际做什么

| 项目 | 第一项：8/16 片，H=4…9 | 第二项：旧口径 no-incumbent 重试 |
|---|---|---|
| 启动脚本 | `run_product_cmax_crossover_after_old_queue.ps1` → `run_mode_cleaning_crossover.ps1` | `run_retry_no_incumbent_old_cmax.ps1` |
| 实例 | 2 个规模 × 6 个清洁间隔 × 3 种模式 = 36 个单元 | N=16/17/20 的纯 2×2，以及 N=20 的 1:1 混合；四例均 H=2 |
| 目标 | 最后产品晶圆返回 LP 的时间；终端清潔任务保留，但其完成不直接延长产品 Cmax | 产品返回和所有已激活清洁末次卸片完成的最大时间 |
| 求解时间上限 | 每实例 14400 s（4 h） | 每实例 28800 s（8 h） |
| 方法/种子 | Proposed；training seed=1、solver seed=1 | 同左 |
| 二阶段 | `stage2_off` | `stage2_off` |
| 其他共享设置 | 4096 MB；optimality emphasis；aggressive heuristics；nonroot separation rounds=0；CUDA policy | 同左 |
| 结束后处理 | 自动独立验解，再 `--require_exact` 汇总 | 脚本仅完成求解和输出；没有后续独立验解、合并及阈值汇总 |

这里 H 是**每腔满片加工周期数**，不是每加工 H 片晶圆清洁一次。2×2 的两次曝光分别参与加工周期计数。不同规模下是否实际出现内部清洁或仅触发终端清洁，须由排程逐例统计。

第二脚本四例按顺序运行。28800 s 并非整批总预算；四例若均耗尽主求解限时，累计主求解预算为 32 h，另有模型读取、推断、存盘等开销。其原始缺解结果限时为每例 14400 s，因而本次主要变化是将单例预算翻倍。长时间重试本身不能保证找到可行解或证明最优。

证据：第二脚本第 32–38 行指定四例，第 50–58 行指定限时、关闭二阶段和求解器设置；`cie/code/run_cie_benchmarks.py:525` 选择每实例时间上限，`:1727` 起对实例依次调用 `_run_one`。

## 3. old Cmax 与 product Cmax 的实际约束

这一区别不仅来自目录名称。旧 `mode_n016_clean02_pure22_equal_total180_20260831.lp:59835` 起包含：

```text
makespan_clean_lb_2_1: +1 c_max -1 clean_front_unload_end_2_1 -10000 clean_active_2_1 >= -10000
```

对激活清洁，这使 `c_max >= clean_front_unload_end`。同一模型说明文件第 82 行明确写明所有激活清洁完成均计入 `c_max`。因此可将旧口径表示为：

```text
C_old = max(max_w C_w, max_active_clean E_clean_front_unload).
C_product = max_w C_w.
```

当前生成器 `petri_mip_generator.py:3914–3924` 只建立产品完成时刻的 makespan 下界，并明确解释终端清洁不延长产品 Cmax；`run_mode_cleaning_crossover.ps1:224` 检查对应模型说明标记。N16/H4/纯2×2 的当前 LP 只有 16 条产品 makespan 下界，没有上述清洁 makespan 下界。附属的 `resource_idle_*` 约束在本次 `stage2_off` 运行开始前会剔除（`environments.py:349–378`），日志记载剔除 13 条约束。

同一可行排程上通常有 `C_old >= C_product`；优化这两个函数可能选中不同排程。将旧最优排程中产品回 LP 时间重新计算出来，只得到新目标的一个可行上界，**不会自动得到新目标的最优性证书**。即使某个旧解恰好满足 `c_max == 最后产品回 LP`，仍应确认它的最优证书来自所声称的目标模型；数值相等不能代替模型口径校验。

## 5. 热启动和可重复性问题

### 5.1 第二项并没有保证实际加载热启动

脚本传入 `--warm_start=auto` 和 `--reuse_existing_solution_as_warm_start`，但四个指定 H2 难例当前均没有相邻的 `*_warmstart.sol` 文件。复用功能首先在**新重试输出目录和新 run label**下查找旧解；脚本没有设置跨目录 `reuse_solution_dir`（参见 `run_cie_benchmarks.py:918–939`）。N16 已完成记录明确为 `reused_solution_warm_start=null`，且日志没有成功加载热启动的记录。因此不能仅凭命令行标志把这四例描述为已提供可行 SPBS。脚本也不执行新的 SPBS 生成阶段。

### 5.2 旧实验与新实验共用可变的实例路径

以旧 campaign 的 `instance_sha256.csv` 中 81 个冻结实例为基准，快照中 **5/81** 个 LP 内容哈希已改变：

- `mode_n016_clean03_pure22_equal_total180_20260831.lp`
- `mode_n016_clean03_mixed11_equal_total180_20260831.lp`
- `mode_n016_clean04_pure22_equal_total180_20260831.lp`
- `mode_n016_clean04_mixed11_equal_total180_20260831.lp`
- `mode_n016_clean05_pure22_equal_total180_20260831.lp`

当前四个 H2 重试实例与旧冻结哈希仍一致，故本次正在运行的四个 LP 未见口径覆盖问题。以上五例集中在新产品口径生成过、且清洁边界实际影响 LP 的单元；重生成导致的差异与目标变更一致。不过，**旧全网格历史结果指向同一路径，不再意味着磁盘文件仍是其当时求解的模型**。投稿包应为不同目标保存不可变实例副本及各自哈希，合并结果时同时核对目标、哈希、种子、预算、配置和验证状态。当前运行期间不要重生成或覆盖这些实例。

### 5.3 H3 总结文件滞后于单例补证

`jms_product_cmax_n8_n16_H3_20260903/summary/mode_cleaning_crossover.md` 标为不完整，因为原批次 N16/H3/纯2×2 超时；但随后 `jms_product_cmax_n16_H3_default_20260903/validation/cie_manufacturing_metrics.csv` 已保存该单元的 `optimal`、gap=0、physical=True、产品 Cmax 一致，Cmax=1402 s。N16/H3 的纯4×1=944 s、混合=1530 s 也已有验证表。

因此 H3 可从已冻结且口径一致的单例补证合并恢复，不能只读取旧 summary 就断言缺证；反之，不同配置补证所得的最优值可作模型比较证据，却不能直接纳入统一配置的求解时间比较。按照用户要求，完整清洁频率相关结果仍应在 H4…9 实验结束并核验后统一写入。

## 6. 对稿件可立即做的修改

1. 在主目标定义之后明确产品返回 LP 截止点、内部清洁与终端清洁的区别。若附录保留旧口径，用不同符号，并说明其表示含清洁卸片的计划完成边界。
2. 模式比较应写成在指定配方与边界下的结论。原主文“各次加工均180 s”使 2×2 每片累计加工360 s，而4×1为180 s；它支持该配方场景的比较，不能独立证明工艺拓扑的普遍优越性。新等累计时长场景能分离这项差异，但不等于已经证实两种真实配方具有相同膜质和工艺能力。
3. 清洁频率补充试验说明应定义 H 为加工周期数、两种工艺各自曝光的计数方法、固定其他参数、三种混流构成、目标边界及内部/终端清洁计数方式。
4. 不把第二重试实验称作“两阶段实验”：两项均明确关闭二阶段。论文中的两阶段等待/节拍效果应由既有等预算工作流试验支撑。
5. 运行状态清楚区分 optimal、timelimit+incumbent、timelimit+no incumbent、infeasible。只对最优证书完整的三模式单元作精确排序；已有可行解可以报告上界，但必须标记 gap 和预算。

## 7. 必须等实验结束并核查后才能补的内容

- 产品口径 N=8/16、H=4…9 完整 36 单元的 Cmax、等效批次吞吐率、内部/终端清洁数，以及与 H3 和其他同口径端点的合并图表。
- 纯模式优劣是否发生切换、切换位于哪个已测区间、混合模式是否最优。实验名称为 crossover 并不保证存在交叉；没有交叉应直接报告未观察到交叉。未测 H=2 的新产品口径不能由旧 H2 重试代替。
- H2 重试的最终可行解覆盖率、是否改善界或最优证书，以及它对旧口径结论完整性的实际贡献。需另行独立验解和合并；若仍缺解，应保留不完整标记。
- 两项补充实验的最终运行次数、最优/可行率和有效证书数。不要提前把它们加入主文既有6273次主实验的统计分母。
- 甘特图和制造结论应取自通过独立验解的完整排程；当前日志中已求解单元的目标值暂不提前写入正文。
